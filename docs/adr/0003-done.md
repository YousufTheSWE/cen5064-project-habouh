# ADR-0003: Account token authentication system and snowflake ID generation

**Date:** 2026-10-15
**Status:** done

## Context

Account registration and login originally lacked a session token mechanism for authenticated actions, and entity IDs needed to be globally unique, 64-bit time-ordered integers without relying on standard auto-increment database sequences. Protected endpoints required a stateless or token-based credential that the frontend could supply in HTTP request headers (`Authorization: Bearer <token>` or `X-Auth-Code`).

## Decision

We implemented an auth token system in the backend where sign-up and sign-in operations issue an authentication token that the frontend stores and sends on subsequent requests. In addition, we introduced a 64-bit snowflake ID generator utilizing the standard Unix epoch (1970-01-01T00:00:00Z) combining millisecond timestamps, sequence numbers, and node identifiers for accounts, communities, posts, and comments.

## Consequences

Protected routes can verify caller identity and authorization without passing raw credentials. Entities have chronological, collision-resistant 64-bit integer IDs suitable for distributed environments and frontend sorting, decoupled from SQLite rowid sequencing.
