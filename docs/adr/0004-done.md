# ADR-0004: Communities, posts, and comments architecture with voting and ownership controls

**Date:** 2026-11-15
**Status:** done

## Context

PostClient required full CRUD capabilities for communities, posts, and comments. We needed to enforce domain rules including a 10-community ownership cap per user, ownership transfer with confirmation by username or user ID, username uniqueness with real-time availability checks, and a voting system where users can upvote (+1), downvote (-1), or clear (0) votes on posts and comments without recalculating aggregates on every query.

## Decision

We built domain entities, SQLite repositories, service classes, and presentation routes for Communities, Posts, and Comments. Community ownership is restricted to at most 10 per user (enforced on creation and transfer). Dedicated `post_votes` and `comment_votes` tables record user vote directions, while atomic delta updates directly maintain cached `upvotes` and `downvotes` integer counters on `posts` and `comments`. On the frontend, usernames are displayed in place of IDs, and confirmation popups protect ownership transfers.

## Consequences

Maintains full social hierarchy (Community -> Post -> Comment) with scalable reads by caching vote tallies rather than executing `COUNT(*)` queries on every page load. Domain business rules and constraints are strictly enforced in both backend service layers and frontend workflows.
